Playbooks

Multi-step workflows that survive restarts, run on a schedule, and can generate new playbooks when asked.

What is a playbook?

A playbook is a named sequence of steps the keprix agent executes in order. Steps can call tools, wait for human input, branch on conditions, or spawn sub-agents. Playbooks persist across sessions and restarts. If a step fails, the playbook resumes from that step on next run - not from the beginning.

Write playbooks in YAML and commit them to your instance. Or tell the agent what you want to automate and ask it to generate the playbook. Either way, the playbook is a file you own, can inspect, and can modify.

Playbook anatomy.

name: daily-borehole-digest
schedule: "0 7 * * *"
steps:
  - tool: fetch_drilling_reports
  params: { region: "northern", days: 1 }
  - tool: summarise_reports
  params: { format: "markdown" }
  - tool: send_telegram_message
  params: { chat_id: "$OPERATOR_CHAT" }

Named and versioned

Every playbook has a name, a version, and a description. The agent can list all playbooks, describe what each does, and report run history.

Step-level durability

Completed steps are marked done. A restart or failure resumes from the first incomplete step. Long-running playbooks do not reset on interruption.

Conditional branching

Steps can branch on the output of previous steps. If a report is empty, skip the summary and send a no-data message instead.

Human-in-the-loop steps

A step can pause and wait for a human response via the configured channel. The playbook resumes when the response arrives - seconds or days later.

Scheduled runs

Attach a cron schedule to any playbook. keprix runs it at the specified time. No separate scheduler required.

Agent-generated playbooks

Tell the agent "create a playbook that does X every morning." It writes the YAML, shows it to you, and registers it after approval.
