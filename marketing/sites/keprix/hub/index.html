session and routing layer

Hub

The keprix hub is the routing layer between your users and the agent kernel. Sessions, auth, and the REST API all live here.

Session management

Each conversation is a session with its own context window, memory reference, and playbook state. The hub creates, suspends, and resumes sessions. Multiple users can have concurrent sessions against the same agent kernel.

Channel routing

Messages from Telegram, Discord, the REST API, and the browser UI all normalise to the same message format before entering the kernel. The hub applies per-channel rate limits and access rules.

REST API

POST /api/message to send a task. GET /api/sessions for session history. Full OpenAPI spec included. Use the API to embed keprix into your own product UI.

Authentication

Three modes: single-user local (no auth), API key (for programmatic clients), and OAuth (for team deployments). Configurable per environment.
