Mutation Engine

When keprix cannot complete a task, it builds the tool it needs and waits for you to approve.

The problem it solves.

Every AI agent framework ships with a fixed tool set. When your task falls outside those tools, the agent either fails or hallucinates. You then write a custom tool, deploy a new version, and try again.

The Mutation engine closes that loop. keprix detects the gap, writes the tool, runs it in isolation, and asks you to approve before it becomes part of the active tool set. No redeployment. No version bump. The instance grows its own capabilities under your supervision.

How it works.

01

Gap detection

The agent kernel runs the tool selection loop. When no registered tool satisfies the task, the kernel sets a gap flag and passes the task description to the Mutation engine instead of failing.

02

Tool synthesis

The Mutation engine calls the configured LLM with the task description, the keprix tool schema contract, and examples of existing tools. The LLM returns a Python function with a typed signature, docstring, and body.

03

Sandbox execution

The candidate tool runs inside an isolated Docker container with no network access and a scoped scratch volume. Stdout, stderr, and return value are captured. The container is destroyed after the run.

04

Approval gate

keprix presents the tool code, the sandbox output, and a plain-language description of what it does. You approve, reject, or edit. Nothing installs without explicit confirmation.

05

Hot registration

An approved tool is written to the tool registry and loaded into the kernel without restarting the runtime. The next request to the same agent has the new capability available immediately.

Safety design.

No auto-install

Every candidate tool must receive an explicit human approval before it is registered. There is no configuration option to bypass this gate.

Sandbox isolation

Candidate tools run in a Docker container with no network and no access to your host file system. The only thing that escapes is captured output.

Code shown first

You see the full Python source before the sandbox run, not after. Reject before execution if the code looks wrong.

Audit trail

Every mutation attempt is logged: task description, generated code, sandbox result, and your decision. The log is queryable and exportable.

Revocation

Installed tools can be disabled or removed at any time from the tool registry. Removal takes effect on the next request without a restart.

Schema contract

Generated tools must satisfy the keprix tool schema: typed input, typed output, a description the kernel can use for selection. Tools that fail schema validation are rejected automatically.

Example: a new data tool.

> Task: "Fetch the latest GHS/USD exchange rate and return it as a float."
> Searching tool registry... no match found.
> Mutation engine: synthesising tool...
> Tool: get_ghs_usd_rate() - 18 lines Python
> Sandbox run: PASS (result: 15.82)
> Approval required. View code? [approve / reject / edit]
