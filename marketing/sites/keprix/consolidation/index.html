Ten agents. One OS.

keprix consolidates the strongest patterns from ten researched agent platforms into one MIT-licensed runtime.

Why consolidate?

Building a production AI agent product today means picking a framework, inheriting its opinions and licence, and fighting its abstractions when your use case diverges. The ten platforms below each solved one part of the problem well. keprix studies those solutions, rebuilds them under one brand and one approval model, and ships them as a cohesive OS.

No upstream runtime dependencies. keprix does not import from any of the platforms below. They are research references. The implementations are original.

The ten capability areas.

01
Agent core and tool loop
Structured function-call loop with tool registration, retry logic, and the approval gate that feeds the Mutation engine. The runtime kernel of keprix.
02
Multi-channel gateway
One agent, many surfaces. Telegram, Discord, REST API, and browser interface. Each channel is an adapter over the same agent core.
03
Research and search workspace
Web search, page fetch, content extraction, and structured synthesis. Agent builds a knowledge base during a session and cites sources.
04
Memory and RAG
Short-term context plus long-term vector retrieval. Sessions persist. Entity memory tracks people, tasks, and decisions across conversations.
05
Durable playbooks and workflows
Multi-step workflows that survive restarts. Playbooks are YAML recipes the agent executes and can generate new ones when asked.
06
Multi-agent teams
Planner and executor architecture. Spawn sub-agents for parallel tasks. Results roll up to a coordinator. All within your instance.
07
Browser automation
Playwright-backed browsing tools. Fill forms, click through flows, capture screenshots, extract structured data from web pages.
08
Analytics and code workspace
Upload CSV, ask questions, get code. Python execution sandbox inside Docker. Charts rendered and returned inline.
09
Governed self-coding
Agent writes code changes, runs tests, proposes a patch. Nothing merges without operator sign-off. The kernel for the Mutation engine.
10
Optional Scout governance connector
Kill switches, tamper-evident audit trails, and operator policy enforcement. Provided by Labyrinth Scout. Optional paid connector. keprix works without it.

Research basis - attribution.

The research phase studied ten open-source agent platforms. The following names are cited here for attribution only. None of their code runs inside keprix. keprix is a clean-room implementation inspired by these works.

Hermes (Nous Research)

Agent core, tool loop, memory architecture, and CLI shell pattern. MIT licensed. The structural starting point for the keprix runtime.

Odysseus

Research agent with deep search and synthesis patterns. Studied for research workspace design. Implementation rebuilt from scratch (AGPL prevents code adoption).

LaVague

Natural-language browser automation. Informed keprix browser tool design. MIT licensed.

SWE-agent

Governed self-coding and patch proposal patterns. Informed the Mutation engine approval flow. MIT licensed.

TaskWeaver

Code interpreter and analytics workspace patterns. Informed the Python execution sandbox design. MIT licensed.

CrewAI, AutoGen, LangGraph, OpenClaw, and others

Multi-agent team coordination and workflow patterns. Each studied for one specific capability. Implementations are original in keprix.
