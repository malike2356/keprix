Roadmap

keprix is pre-release. Phase 0 is the foundation. Each phase builds on the last.

Phase 0 - Foundation (current).

The agent kernel, tool loop, CLI shell, memory architecture, and Docker Compose deployment are committed. The Hermes codebase (Nous Research, MIT) has been adopted and renamed. The foundation is stable.

Done - agent kernel

Tool loop, LLM routing, function-call executor, retry logic. 2301-file Python foundation committed to main.

Done - CLI shell

Interactive terminal shell, model switching, session management, developer identity system.

Done - memory layer

Short-term context window, long-term vector store via pgvector, entity extraction.

Done - Docker deployment

docker-compose.yml with keprix, PostgreSQL, Redis. Three-command install on any Linux host.

Phase 1 - Capability ports.

Port the ten consolidated capabilities from their research base into production-grade keprix tools. Each capability becomes a set of registered tools with tests and documentation.

Multi-channel gateway

Telegram and Discord adapters. REST API. Browser UI. All routing through the hub.

Research workspace

Web search, page fetch, content extraction, structured synthesis. Session-persistent knowledge base.

Mutation engine body

Gap detection, tool synthesis prompt, sandbox execution, approval gate. The _trigger_mutation() stub becomes a full implementation.

Playbook engine

YAML playbooks, step-level durability, conditional branching, scheduled runs, agent-generated playbooks.

Browser automation

Playwright-backed tools: navigate, fill, click, screenshot, extract. Runs in the tool sandbox.

Analytics workspace

File upload, Python code execution, chart generation. Powered by the tool sandbox.

Phase 2 - Stabilisation.

2.1

Integration test coverage

End-to-end tests for all ten capability areas. CI gate on all pull requests.

2.2

Scout governance connector

Public API contract for the optional Labyrinth Scout sidecar. Documentation and reference integration.

2.3

Helm chart

Kubernetes deployment for production-scale and high-availability configurations.

Phase 3 - Public release.

v1.0.0 release. Domain live. GitHub discussions open. Contributing guide published. All ten capabilities documented with examples.

The roadmap after Phase 3 is community-driven. Feature requests go through GitHub Discussions. Accepted features are scheduled into minor version milestones.
