# keprix - Prompt 108: PDF And Structured Document Export

## Context

Read `10-workspace-documents-notes-calendar.md`,
`superseded-05-tools-and-terminal.md`, and
`107-external-human-review-gateway.md`. Tool implementations live under `src/keprix/tools/`.

keprix's workspace stores notes and documents as Markdown. Many downstream uses require a rendered, immutable export: compliance reports for audit, hazard logs for sign-off, research summaries for clients, generated contracts for legal review. Markdown is not acceptable as a formal deliverable in these contexts.

This prompt builds a general-purpose export service. It converts Markdown, structured JSON, or workspace document references into PDF or well-formatted HTML, with an optional cover page, metadata block, and signatory section for documents that require human sign-off evidence.

The export service is a tool (registered in the keprix tool registry per Prompt 05) and also has its own API surface for direct use by playbooks, the workspace UI, and the review gateway (Prompt 117).

## Rendering Pipeline

### Stage 1: Markdown to HTML

Use `mistune` (pure Python, no system deps) to convert Markdown to HTML.

Apply the following transformations after rendering:

- Sanitize with `bleach`: allow `h1`-`h6`, `p`, `ul`, `ol`, `li`, `table`, `thead`, `tbody`, `tr`, `th`, `td`, `code`, `pre`, `blockquote`, `strong`, `em`, `a` (href only), `img` (src only, local paths only), `br`, `hr`.
- Reject `script`, `style`, `iframe`, `object`, `embed`, `form`, `input`.
- For `img` tags: resolve relative paths against the workspace file store. Reject `http://` and `https://` src values (no remote image fetch).
- Wrap in the `document.html` template which applies consistent typography, page margins, and print CSS.

### Stage 2: Cover Page (optional)

If `include_cover` is true, prepend an HTML cover page generated by `cover_page.py`:

```
Field             Source
---------         ------
Document title    required in export request
Document type     required (e.g. "Hazard Log", "Compliance Report", "Research Summary")
Version           optional (e.g. "v1.4")
Date generated    server-side NOW() at export time (never from caller)
Workspace name    from workspace record
Prepared by       optional (agent name, playbook name, or "keprix")
Classification    optional free text (e.g. "CONFIDENTIAL", "DRAFT", "FOR REVIEW")
```

The cover page uses a clean single-column layout with a horizontal rule separating it from the document body. No keprix logo on the cover unless the workspace has set a custom logo. No Verlox branding.

### Stage 3: Signatory Block (optional)

If `include_signatory` is true, append an HTML signatory section after the document body:

```html
<section class="signatory-block">
  <h2>Sign-off Record</h2>
  <table>
    <tr><th>Reviewer</th><td>{{ reviewer_name }}</td></tr>
    <tr><th>Role</th><td>{{ reviewer_role }}</td></tr>
    <tr><th>Organisation</th><td>{{ reviewer_org }}</td></tr>
    <tr><th>Decision</th><td>{{ decision }}</td></tr>
    <tr><th>Decided at</th><td>{{ decided_at }}</td></tr>
    <tr><th>Note</th><td>{{ reviewer_note }}</td></tr>
    <tr><th>Review request ID</th><td>{{ review_request_id }}</td></tr>
  </table>
  <p class="signatory-legal">This record was generated by keprix review gateway. The decision was submitted via a cryptographically signed single-use link by the named reviewer.</p>
</section>
```

Signatory data is passed in by the caller (typically a playbook step that runs after Prompt 117 decides). The export service does not fetch review decisions itself; it only renders what it receives.

### Stage 4: PDF Rendering

Try WeasyPrint first:

```python
from weasyprint import HTML, CSS
pdf_bytes = HTML(string=full_html).write_pdf(
    stylesheets=[CSS(filename="assets/print.css")]
)
```

If WeasyPrint is not installed (checked with `importlib.util.find_spec`), fall back to Playwright headless Chromium:

```python
async with async_playwright() as p:
    browser = await p.chromium.launch()
    page = await browser.new_page()
    await page.set_content(full_html)
    pdf_bytes = await page.pdf(format="A4", print_background=True, margin={"top": "20mm", ...})
    await browser.close()
```

If neither is available, return the rendered HTML instead of PDF and set `Content-Type: text/html` in the response. Log a warning: "PDF engine not available; returning HTML. Install WeasyPrint or Playwright for PDF export."

Do not fail silently. The API response must always indicate which format was actually returned.

## Supported Input Types

| Input type       | Description                                        |
|------------------|----------------------------------------------------|
| `markdown`       | Raw Markdown string in the request body            |
| `document_id`    | Reference to a workspace document (Prompt 10)      |
| `note_id`        | Reference to a workspace note (Prompt 10)          |
| `structured_json`| JSON object; rendered as a structured table report |

For `structured_json`, the renderer produces a two-column key-value table for scalar fields and an expandable detail table for nested objects and arrays. This is useful for rendering agent-generated reports (hazard log entries, research findings, opportunity scores) without requiring the caller to format Markdown first.

## Export Tool (Tool Registry)

Register in the tool registry (Prompt 05) as `export_document`:

```python
class ExportDocumentTool(BaseTool):
    name = "export_document"
    description = (
        "Convert a document, note, or structured content to PDF or HTML. "
        "Use when you need a formatted, immutable file a human can review or sign. "
        "Returns a file URL that can be attached to a review request or downloaded."
    )
    parameters = {
        "type": "object",
        "properties": {
            "input_type": {"type": "string", "enum": ["markdown", "document_id", "note_id", "structured_json"]},
            "content": {"type": "string", "description": "Markdown text, document/note ID, or JSON string"},
            "title": {"type": "string"},
            "document_type": {"type": "string", "description": "e.g. Hazard Log, Compliance Report"},
            "version": {"type": "string"},
            "include_cover": {"type": "boolean", "default": True},
            "include_signatory": {"type": "boolean", "default": False},
            "signatory_data": {"type": "object", "description": "Only if include_signatory is true"},
            "format": {"type": "string", "enum": ["pdf", "html"], "default": "pdf"},
            "classification": {"type": "string", "description": "e.g. CONFIDENTIAL, DRAFT"}
        },
        "required": ["input_type", "content", "title"]
    }
    risk_level = "low"
    requires_approval = False
```

The tool stores the generated file in the workspace file store (Prompt 10) under `exports/{timestamp}-{slug}.pdf` and returns the file URL.

## API Endpoints

```
POST /api/export
     Body: {
       input_type, content, title, document_type?, version?,
       include_cover?, include_signatory?, signatory_data?,
       format?, classification?
     }
     Returns: {
       file_url: string,       - workspace-scoped URL for download
       format_returned: string, - 'pdf' or 'html' (may differ from requested if PDF engine unavailable)
       filename: string,
       size_bytes: number
     }

GET  /api/export/{file_id}
     Returns: file download (Content-Disposition: attachment)

GET  /api/export/{file_id}/inline
     Returns: file for browser display (Content-Disposition: inline)
```

Both GET endpoints require workspace authentication.

## Acceptance Criteria

- POST `/api/export` with `input_type: markdown` and a Markdown body returns a PDF file.
- The PDF includes a cover page when `include_cover: true` with correct title, document type, and generated date.
- The PDF includes a signatory block when `include_signatory: true` and `signatory_data` is provided.
- A `document_id` input resolves to the workspace document text and exports correctly.
- A `structured_json` input renders as a readable table layout in the PDF.
- If WeasyPrint is unavailable, the endpoint returns HTML and sets `format_returned: html` in the response; it does not return HTTP 500.
- Remote image URLs in Markdown are stripped; the document still renders without error.
- Script tags in Markdown are stripped before rendering.
- The `export_document` tool is callable by an agent; the returned file URL is usable as an artifact in the review gateway (Prompt 117).
- Files are stored under `exports/` in the workspace file store, not in a temp directory that is cleared between restarts.
