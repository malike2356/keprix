# keprix - Prompt 34: Documentation Site and Landing Page

## Purpose

Build the documentation site and the public landing page for keprix.

Good documentation is not a nice-to-have. It is the primary distribution channel for an
open-source product. A developer who cannot find how to configure something in under
2 minutes will leave. This prompt builds the infrastructure to prevent that.

## Documentation Site

### Technology

MkDocs Material. Chosen because:
- Generates a static site (can be hosted on GitHub Pages, Netlify, or self-hosted).
- Excellent search.
- Supports versioning, code tabs, admonitions, and navigation.
- Markdown source stays close to the codebase.

Location of docs source: `docs/` in the keprix repository.

### Auto-Generated Reference Pages

Two pages must be generated automatically from source, not hand-written:

1. `prompts-archive/ref-api.md`: Generated from the OpenAPI spec at `GET /api/openapi.json`. Use
   `mkdocs-swagger-ui-tag` or render directly from the OpenAPI spec.

2. `prompts-archive/ref-cli.md`: Generated by running `keprix --help` and all subcommands and
   formatting the output into a table.

3. `configuration/environment-variables.md`: Generated by parsing `.env.example` comments
   into a structured table with columns: variable name, description, default, required.

Add a `scripts/generate-docs.sh` that runs these generators before the MkDocs build.

### MkDocs Configuration

`docs/mkdocs.yml`:
- Theme: Material.
- Features: navigation tabs, search, code copy, content tabs, dark/light toggle.
- Plugins: search, minify, git-revision-date.
- Primary color: use the keprix brand color.
- Repo URL: `https://github.com/malike2356/keprix`.
- Edit URI: `edit/main/docs/` (enables "Edit this page" links).

### Writing Standards

All documentation must follow the engineering pillars:
- Plain language. No jargon without definition.
- No emojis. No em dashes. No en dashes.
- Short paragraphs (3-4 sentences max).
- Every code block has a language tag.
- Every admonition (note, warning, tip) is used sparingly and purposefully.
- Commands are tested before being documented.

### Quickstart (must work in under 5 minutes)

The quickstart at `getting-started/quickstart.md` is the most important document. It must:

1. Assume only Docker and Docker Compose are installed.
2. Show three commands (clone or curl, configure, compose up).
3. Show what to expect at `http://localhost:3000`.
4. Include a screenshot (placeholder path if not yet available).
5. Link to first-run walkthrough for what to do next.
6. Troubleshooting section with the three most common errors.

## Landing Page

The landing page is a separate static HTML/CSS page (not MkDocs) at the root of a
`landing/` directory. It is served from GitHub Pages or a CDN.

### Landing Page Structure

Single page layout:

```
Header
  Logo, "keprix", tagline, "Get Started" and "GitHub" buttons.

Hero section
  Main headline: "Your AI agent. Your server. Your rules."
  Subheadline: short description (2 sentences max).
  CTA: "Install in 5 minutes" (links to quickstart).
  Secondary CTA: "View on GitHub".

What it is (3 columns)
  1. AI-powered workspace: chat, documents, email, research, scheduling.
  2. Cyber security toolkit: OSINT, forensics, vulnerability scanning, SIEM.
  3. Self-hosted: your data stays on your machine. No subscription required.

Feature comparison table
  keprix (Community) vs Aiva (commercial, separate product) (Managed Enterprise).
  Rows: key features. Columns: included in keprix, included in Aiva.
  "Get Aiva" button for enterprise row.

Quickstart code block
  The one-command install. Copy button.

Community section
  GitHub stars badge, contributor count.
  "Join the community" links: GitHub Issues, GitHub Discussions.

Footer
  Links: Docs, GitHub, Aiva (enterprise), Scout (governance).
  License: MIT.
  Copyright.
```

### Landing Page Tech

Plain HTML, Tailwind CSS (CDN), minimal JavaScript. No React, no build step. The page must
load in under 1 second on a 3G connection.

Use system fonts. No Google Fonts (privacy).

Mobile-first responsive design.

## Acceptance Criteria

- `scripts/build-docs.sh` runs without errors and produces a `site/` directory.
- The quickstart page contains no more than 5 commands.
- `prompts-archive/ref-api.md` is generated from the live OpenAPI spec, not hand-written.
- `configuration/environment-variables.md` lists every variable from `.env.example`.
- The landing page loads in under 1 second (measured by `lighthouse --only-performance`).
- No broken links in the docs site (checked by test_links.py).
- The feature comparison table accurately reflects the actual feature gate configuration from
  Prompt 01 (no marketing claims that do not match the code).
- No emojis, em dashes, or en dashes appear anywhere in the docs or landing page.
