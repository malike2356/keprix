## 1. What this prompt builds

End-to-end **session pattern detection -> skill proposal -> pack creation -> improvement loop** (Chase Level 1 loop engineering for skills).

Consumes:

- **256** `WorkflowAuditResult` via `/api/agent-os/audit/{id}/export-to-proposals`
- Completed chat sessions from SessionDB

Delivers:

- Pattern detector on session completion (background, configurable)
- Proposals dashboard (`/agent-os/skill-proposals`)
- Approve flow creates real skill packs under `{KEPRIX_HOME}/skills/`
- `SkillImprovementLoop` reviews runs and surfaces proposals
- Weekly review report (`/agent-os/skill-review`)

**Non-goals:** Auto-apply improvements without opt-in; no fake pattern data.

## 3. Architecture

```text
Session completes
        |
        v
session_pattern_detector.py  (async job, min 3 occurrences)
        |
        v
skill_proposer.py  -->  proposals store
        |
        v
UI /agent-os/skill-proposals  [Approve | Edit | Reject]
        |
        v
skill_packager.py  -->  ~/.keprix/skills/{slug}/SKILL.md + tests fixture
        |
        v
skill_improvement_loop.py  (on each headless/chat skill run)
        |
        v
skill_review_reporter.py  (cron weekly, configurable)
```

## 6. Settings (`/settings/agent/self-improvement`)

- Watch sessions for patterns (on/off)
- Propose at N+ occurrences (default 3)
- Min confidence (default 0.7)
- Auto-create skills (off by default)
- Auto-apply improvements (off by default)
- Weekly report schedule
- Ignored pattern keywords

## 8. Acceptance criteria

- Import from **256** creates pending proposals.
- **256** export rows use `source: "audit"`, `origin: "workflow_audit"`, `audit_id`, `slug`, `name`, `description`, `evidence_sessions`, and `status`.
- After 3 similar sessions (configurable), pattern detector creates proposal with real session IDs.
- Approve writes valid `SKILL.md` (frontmatter passes skill standards) and registers slash command.
- Improvement loop opens proposal when same follow-up action appears 3+ times in skill run history.
- Weekly report is generated by scheduled job and viewable in UI.
- No stub returns in API paths; tests use fixture sessions on temp `KEPRIX_HOME`.
